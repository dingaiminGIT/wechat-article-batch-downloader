# 公众号批量归档：原生通道本机预览版

版本：1.1.0（本机体验版，build 12）。2026-09-21 已用新包后台完成“每天晒白牙”21 页 / 207 篇历史列表读取，以及其中 30 篇真实正文与图片导出；非本人运营账号“小盖fun”也完成 3 页 / 30 篇真实正文及图片导出。合计 60 篇新下载，不把仅有链接算成正文下载。后续体验问题复测又通过界面下载 AI白牙 5 篇。用户在 build 11 发起的每天晒白牙 207 篇批次也已完成（任务汇总 completed=207，failed=0）。仅针对当前本机环境验证，不能称为通用稳定版。

## 解决什么问题

归档自己可正常访问、但不由自己运营的公众号文章，不需要公众号管理员权限。主界面支持读取最近若干篇、全部历史或日期范围，再批量导出 HTML、Markdown、纯文本及 JSONL；图片复用现有导出器保存。

本轮目标是修复“所有公众号都读到 0 篇”的列表入口，不涉及微信读书。

## 为什么以前能用，现在不行

此前使用 `/mp/profile_ext?action=getmsg`。本机实测中它可能返回 HTTP 200、ret=0，却没有可用历史列表。1.0.3 增加了 `/mp/author?action=get_articles`，但它依赖真实 author_id；把 gh_ 开头的公众号用户名当作 author_id 并不能覆盖普通公众号。此前一个账号读到 7 篇，只能证明该账号路径有效，不能证明普遍兼容。

2026-09-21 的“每天晒白牙”测试又确认：普通文章页可以注入诊断脚本，也有 WeixinJSBridge，但直接调用 H5ExtTransfer 返回 fail。因此新实现不再从普通文章页调用原生历史列表。

## 实现原理

1. **建立本机连接。** 下载器启动独立 Node 连接组件，验证微信版本、关键文件指纹及唯一登录账号。沿用已验证的 WMPFDebugger 运行时，不修改微信文件。
2. **用小程序初始化调试通信。** 现有适配器依赖小程序建立本机通信。小程序不是文章来源，也不需要在小程序里搜索公众号。
3. **从微信原生公众号主页读取列表。** 选择 `weixin://resourceid/SubscriptionProfile` 或对应订阅页面，通过 WeixinJSBridge 的 `H5ExtTransfer` 调用 `bizprofilev2h5`。身份由当前微信会话补充，不提取登录数据库内容，不把账号 Cookie/key 写进新连接组件日志。
4. **逐页保存。** 使用微信返回的不透明 Offset 游标；校验返回码、公众号用户名、结束标记及游标推进。每页原子保存文章列表、游标、账号绑定和已访问游标摘要。
5. **下载正文。** 新原生模式在已打开的微信文章网页上下文中同源请求文章 HTML，交给既有导出器解析并保存。新包后台已真实导出两个账号合计 60 篇的 HTML、Markdown、TXT 与 JSONL；不把其余列表链接算作已下载正文。

列表读取与正文下载是两个独立阶段。读到链接不代表正文、图片已全部下载。

## 怎么使用

1. 打开下载器，在「开始归档」第一步点“连接微信”；公众号页的连接按钮也紧邻状态说明。
2. 先启动连接，再在微信中打开“发现 → 小程序 → 腾讯文档”，停在小程序首页即可，不需要打开、创建或编辑文档，也不需要授权额外权限。若一直等待连接，请关闭小程序后重新打开。2026-09-21 的对照测试已验证：断开旧通道、关闭文档窗口并重启连接后，仅打开首页即可从 waiting_miniapp 变为 ready；“必须打开文档”不是成立的要求。此前未连接的具体原因尚未完全隔离，不能仅凭这次成功断言其唯一原因是加载时机。
3. 打开目标公众号的一篇文章，确认正文正常显示，再点击公众号名称进入主页。保留文章、小程序及主页窗口。主页也可识别账号和读取列表，但下载正文前仍建议打开目标账号的一篇正文；本机“小盖fun”实测在仅开主页时正文请求要求验证，打开其正文后恢复。若出现验证，手动处理后再继续。
4. 顶部显示原生读取就绪后，选择左侧公众号和读取范围，点击读取。
5. 读取列表不会自动下载。点击“下载全部”或“下载所选”后，先弹出确认框，核对公众号、篇数并选择模式，确认后才会预检正文、添加任务。正文预检失败会弹出原因。稳妥模式的正文请求间隔至少 2 秒，快速试验模式至少 1 秒，不采用旧 HTTP 通道的 500 毫秒策略；实际速度还取决于图片数量和微信响应。两种模式遇到验证均暂停，不自动绕过或反复重试。
   下载中心的活动批次提供“暂停下载 / 继续下载 / 终止下载”。暂停和终止立即阻止后续排队任务，正在导出的文章会收尾完成，以免留下半截文件。终止需要再次确认，保留已保存文件及任务记录，终止批次不能继续；重新选择文章可创建新批次。添加过程中“停止添加”仅停止尚未提交的部分，不等于暂停已经提交的任务。
6. 关闭窗口、切号、断线时先重新连接，再继续。旧版整数 offset 与新原生游标不兼容，旧扫描需要“重新读取”；已下载文件不主动删除。

本版本为提高可验证性，要求批量期间保留小程序窗口。早期实验已证明初始化后可以把只读连接留在主页并关闭小程序，但这一优化没有纳入当前安装包，不能当作本版已交付能力。

微信完全退出重启后的复测也已通过：旧通道先报告会话失效；重新连接后，将提前打开的小程序关闭并重开，仅停腾讯文档首页即恢复 ready。启动顺序影响当前实现的连接触发，不是必须读取文档内容。

## 本地应用交互调整

- 连接按钮位于首页第一步旁、公众号页状态说明下方，不再放在最右侧。顶部报告通道状态与本次识别的账号数量，不暗示当前屏幕里任意公众号都能读取；等待小程序时不要求点进文档。
- build 11 修正原生分栏详情区的尺寸反馈，防止表格撑高整个窗口内容，导致侧栏上移、下载栏消失。下载操作区放在列表上方，文章表格独立滚动；使用独立标题栏避免与窗口按钮重叠。
- 左侧区分「本次已识别」与仅保存在本机的账号，不把全局连接成功当成所有账号都已识别。
- 连接或正文窗口未就绪时，点击读取 / 下载会明确弹出所缺条件；不会静默提交。打开已保存目录不依赖微信，固定交给 Finder 打开并检查错误。
- 空列表区分尚未读取、正在读取与中断，不再把未完成误导成没有文章。
- 默认稳妥模式；恢复真实生效的快速试验选项（1 秒），选择只影响新创建任务。日期和篇数输入先校验。
- 设置改为原生连接；旧版网络恢复仅保留在排障区，不再引导安装证书。
- 移除网页内旧批量浮层：其历史列表路径未通过本轮可靠性验证。独立单页导出代码保留，不能据此宣传旧批量路径有效。
- 本地下载目录在后台扫描，避免文件访问等待卡住整个窗口；扫描只读，不自动改名已有目录。
- 不把历史任务数当作实际本地文件数。目录不存在时明确提示原路径已移动或删除，不创建空目录假装成功，也不要求重连微信。
- 任务预检、添加进度、最终新建 / 跳过 / 失败数量都有反馈；成功入队不等于正文下载完成。

## 如何应对变化

- 适配器独立于导出器：列表接口变动不必重写文件导出。
- 版本和组件指纹先检查，不用未经验证的偏移尝试连接新微信。
- 账号识别同时支持文章页与原生公众号主页；主页按公开 userName 和列表文章中的 biz 交叉校验，不把昵称相同当成同一个账号。
- 不把 HTTP 成功等同于数据成功，也不把桥接失败当作 0 篇完成。
- 校验账号绑定，切换账号后不能沿用另一个账号的读取断点。
- 单独检查微信网页辅助进程的存活与启动时间；辅助进程重启后提示重新连接，再重新打开小程序，避免永久显示“等待小程序”。
- 按 biz/mid/idx 去重，不以消息组 ID 或临时签名去重。
- 对重复游标、无新增内容、缺少结束标记、迁移提示停止并保留进度。
- 验证码或原生连接异常会暂停同一批次，不持续请求剩余文章。
- 本机控制接口只监听回环地址，组件间使用随机令牌，拒绝带网页 Origin 的原生控制请求；不开放通用远程 eval 接口。

这些措施能让变化更容易发现、定位和适配，不能保证微信未来更新永不失效。接口属于客户端内部实现，不是官方承诺稳定的开放下载 API。

## 当前限制

- 仅适配 Apple Silicon、微信 4.1.13 / WMPF 269602，以及本机已经准备的辅助进程指纹；不是适合任意 Mac 的公开稳定版。
- 微信主窗口右侧正文面板并不保证进入当前读取通道。江苏新闻这一打开路径实测未出现在通道可见页面中；该路径尚未通过自动识别验收。需点击正文中的公众号名称进入主页，并以界面实际列出的本次识别账号为准，不能把绿色连接状态当作识别成功。
- 不会自动重签微信、关闭 SIP、安装证书或接受新的系统权限。
- 不保证已删除、付费未购、访问受限的内容可下载；遇到验证码暂停，由用户在微信处理，不自动绕过。
- 音视频、外链和特殊文章版式沿用旧导出器能力，不能承诺全部离线还原。
- 首轮被锁屏阻塞；用户解锁并手动打开小程序内容页后，新包后台真实验收已取得结果。computer use 的坐标点击仍失败，因此不把后台 API 验收等同于全部界面操作已验收。
